# Что изменилось в v2.2

- `media_images.py`: безопасный MIME-экстрактор изображений, JPEG-транскодинг без EXIF, лимиты 4 фото/4 МБ, без внешних URL.
- `vision.py`: OpenAI-compatible multimodal запрос только для реально присутствующих изображений; строгий JSON и SQLite-кэш по хэшу файла/модели/endpoint. Доступность vision не предполагается автоматически.
- `segmentation_llm.py`: LLM-сегментация по индексам строк для всех фаз обучения и для инференса. Старые цитаты предварительно убираются; текст не переписывается. Валидатор + fallback.
- `train.py`, `signals_v2.py`, `analyze.py`: подключена сегментация в обучение/анализ (флаг `--llm-segmentation`), отдельные метаданные модели. При недоступной обязательной LLM-сегментации результат помечается UNCERTAIN.
- `analyze.py`: итог 80% текста + 20% vision-score **при наличии обоих сигналов**; без фото и при отказе vision текст не меняется, при сильном конфликте UNCERTAIN; полные поля `photos`, `text_final_score`, `text_verdict`. Прежнее дерево и файл модели не ломаются.
- `test_my_text.py`: `--image path` (повторяемый), поддержка сообщения только с фото (результат UNCERTAIN + оценка фото).
- `api.py`, `config.py`: раздельные VISION_MODEL, VISION_API_URL, VISION_API_KEY с наследованием от chat-LLM. Оригинальный `.env` сохраняется на ПК.
- `09_QWEN_ENV_LLM_TRAIN.bat`: теперь включает LLM-сегментацию при переобучении.
- `12_QWEN_ENV_LLM_IMAGE_TEXT.bat`, `13_QWEN_ENV_LLM_EML.bat`: Windows-интерфейсы для мультимодального сообщения/почты.
- `requirements.txt`, `requirements-local-lock.txt`: Pillow для безопасной конвертации изображений.
- `tests/test_multimodal.py`: тесты MIME, роутинга, отказоустойчивости, границ LLM, фьюжна.

**Ограничение:** определение AI-генерации по одной фотографии недостоверно. Веса и итоговые пороги для фото не обучены и не откалиброваны на мультимодальных метках. Реальные сервисы локальной Qwen и API из пользовательского `.env` недоступны в тестовой среде.
