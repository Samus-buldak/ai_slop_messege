# Kirusha v2.2 — фото в сообщении + LLM-сегментация

## Что работает

**SMS/текст с фото:** можно прикрепить JPG, PNG, WebP, GIF (используется первый кадр), BMP или TIFF через `--image`. В `.eml` детектор сам найдёт `image/*` MIME-вложения, в том числе inline/CID. **Если изображения нет, никакого vision-запроса нет.** Ссылки на картинки из интернета не скачиваются — чтобы не отправлять сторонние запросы и не получать данные без явного вложения.

Фотографии очищаются от EXIF/GPS и сжимаются в JPEG (макс. 1280 пикселей по стороне), после чего отправляются в OpenAI-совместимый vision `/chat/completions`. До 4 вложений, каждый исходник до 4 МБ. Маленькие tracking-пиксели и потенциально опасные файлы отбрасываются.

**LLM-сегментация:** при обучении с `--llm-segmentation` и при последующем анализе письма LLM возвращает только границы строк: `greeting_end`, `signature_start`. Из них выделяются `greeting`, `body`, `signature`; контекстные признаки считаются по тексту текущего автора, без цитат. `subject` извлекается напрямую из заголовка. В предыдущей стадии удаляются старые цитаты и пересланная переписка. LLM не имеет права переписывать содержимое. Границы строго проверяются, недостоверный/неполный ответ заменяется сегментацией по правилам и отмечается как fallback. Для прежних обученных моделей используется их прежняя сегментация.

## Установка (Windows)

1. Скопируй файлы PATCH поверх своей папки проекта с заменой, но **сохрани `.env`, `.venv-local`, `data/`, `model*/`**.
2. Обнови зависимости, если Pillow не установлен:

   ```powershell
   .\.venv-local\Scripts\python.exe -m pip install "Pillow>=10,<13"
   ```

3. Убедись, что Qwen embeddings загружены в LM Studio на порту 1234. Запусти `03_LOCAL_QWEN_CHECK.bat`.
4. Выполни **`09_QWEN_ENV_LLM_TRAIN.bat`**. Он теперь запускает `--with-llm --llm-segmentation`: центроиды, деревья и пороги пересчитываются с новой сегментацией. LLM вызывается и для сегментации обучающей выборки — понадобится время/квота внешнего API. Обучение использует размеченные **текстовые** письма; изображения не входят в обучающие признаки дерева.
5. Выполни **`12_QWEN_ENV_LLM_IMAGE_TEXT.bat`** (вручную укажи путь к фото или оставь пустым) либо `10_QWEN_ENV_LLM_TEXT.bat` для только текста. Текст вводится до отдельной строки `END`. Ещё один способ — командная строка:

   ```powershell
   .\.venv-local\Scripts\python.exe local_qwen.py text --llm-from-env --image "C:\Users\you\Pictures\photo.jpg"
   .\.venv-local\Scripts\python.exe local_qwen.py text --llm-from-env --image "photo1.jpg" --image "photo2.png" "message.txt"
   .\.venv-local\Scripts\python.exe local_qwen.py analyze --llm-from-env "letter.eml" --json
   ```

6. Для почты можно перетащить `.eml` на **`13_QWEN_ENV_LLM_EML.bat`**. В API `POST /analyze` достаточно передать `.eml` или multipart поле `file` — вложения разберутся автоматически. Лимит HTTP-запроса: 5 МБ.

**LLM для фото:** исходная модель из `.env` может быть *text-only*. Тогда проверка фото пропустится (предупреждение в результате) и итог останется текстовым. Необходимо, чтобы `MODEL` поддерживал изображения, либо указать **`VISION_MODEL=название_vision_модели`** в `.env` при условии что тот же API действительно её предоставляет. Можно отдельно задать `VISION_API_URL` и `VISION_API_KEY`, если vision-модель расположена у другого совместимого провайдера. Не сохраняй ключи в Git и не присылай в чат. `VISION_MODEL` по умолчанию совпадает с разговорной LLM из `.env`.

## Как объединяются оценки

**Текст (как в v2.1):** Qwen Embeddings локально + контекст + оценки chat-LLM по сегментам → Decision Tree → `text_final_score` от 0 до 1. Если модель заново обучена с LLM-сегментацией, сегменты из LLM используются и на обучении, и на инференсе.

**Фото (только при наличии):** vision LLM получает каждое вложение и возвращает JSON `assessable`, `score` от 0 до 1 и `reason`. Если оценить нельзя — `score=null` и фото не влияет на итог. Для нескольких оценённых изображений берётся среднее `image_score`.

При наличии текста и хотя бы одной успешной оценки фото итоговый **эвристический** скор:

```
final_score = 0.80 * text_final_score + 0.20 * image_score
```

Если фото нет, **`final_score == text_final_score`**. Если модель изображений недоступна/не поддерживает фото, тоже остаётся старый текстовый скор. Конфликт сильных оценок текста и изображения даёт `UNCERTAIN` (ручная проверка). Для сообщения **только с фотографией** возвращается оценка фото отдельно, но итог `UNCERTAIN`: нет обученного мультимодального классификатора. При неудачной обязательной LLM-сегментации `UNCERTAIN` остаётся даже с оценкой изображения.

В JSON представлены `text_final_score`, `photos.count`, `photos.checked`, `photos.image_score`, `photos.items[].score`, `photos.items[].reason`, `final_score`, `text_verdict`, `verdict`, `segmentation_method`. **Эти числа не являются доказанными вероятностями**: визуально установить, сгенерирована ли картинка нейросетью, по одному изображению обычно нельзя. Текущий вес 20% выбран эвристически, не обучен на изображениях, и новые пороги не калиброваны на мультимодальном датасете. Для достоверной оценки нужно собрать размеченные фото, отдельно проверить зрительный детектор и откалибровать итог на реальных письмах с вложениями.

## Конфиденциальность

**Локальные Qwen embeddings** получают только текст. **Внешняя LLM из `.env`** в режимах `--llm-from-env` получает текст для сегментации и оценки, а при наличии фото — и очищенное от метаданных изображение. Запуск без `--llm-from-env` не обращается к исходному внешнему API; если vision-модель локально не настроена, фото не оценится. Не анализируй чужие личные изображения без разрешения.

## Что проверено

Тесты с имитацией HTTP-сервера: без фото vision-запросы отсутствуют; вложенное фото отправляется на vision `/chat/completions` с data URL; ошибка vision не подменяет оценку; JSON-границы LLM-сегментации применяются без переписывания текста; невалидный JSON даёт fallback; подсчёт итоговой оценки 80/20. Тест с реальными серверами LM Studio и твоего `.env` нужно выполнить на твоём ПК.
