# Проект с нуля и локальный Qwen

## Что делает проект

Это экспериментальный детектор авторства электронных писем. На входе — письмо
в формате `.eml` или обычный текст через `test_my_text.py`. На выходе — `HUMAN`
(похоже на человека), `AI` (похоже на ИИ), `UNCERTAIN` (нужна ручная проверка).
Это оценки по обучающим примерам, а не доказательство авторства.

Письмо → разбор текста → четыре части → числовые признаки → дерево решений → результат.

Четыре части: тема, приветствие, основной текст, подпись. Разделение основано
на правилах в `segments.py`, а не на отдельной нейросети. Вложения не анализируются.

## Три источника признаков

1. **TF-IDF и логистическая регрессия.** TF-IDF превращает слова и пары слов в числа.
   Регрессия обучается на примерах и оценивает, какому классу ближе такой набор слов.
   Это небольшая локальная модель, ей не нужны LM Studio или видеокарта.
2. **Qwen Embedding.** Превращает текст в вектор — список из 1024 чисел.
   Похожие по смыслу тексты обычно дают близкие векторы. При обучении детектор
   вычисляет средние векторы человеческих и ИИ-писем отдельно для каждой части.
   При проверке сравнивает вектор новой части с этими средними.
   Qwen не выдаёт непосредственно вероятность авторства; оценку строит код проекта.
3. **Необязательная разговорная LLM.** Получает текст и просьбу оценить ИИ-авторство.
   Это отдельная роль и отдельная модель. В подготовленном локальном режиме эта
   ветка выключена: для задачи подключения эмбеддингов она не требуется.

Дерево решений объединяет признаки. В нём 10 входов: четыре оценки частей,
четыре признака их наличия и два средних значения. Финальный скор — среднее
между ответом дерева и средней оценкой непустых частей. Пороги определяются
на отдельной калибровочной выборке. Если части дают конфликтующие метки,
код может вернуть `UNCERTAIN`.

`no_llm` в выводе означает отсутствие разговорной оценки LLM. **Эмбеддинги Qwen
в этом режиме могут и должны работать.** Их наличие видно в столбце `EMBED`
и в `embedding_backend: api`. Здесь `api` обозначает способ обращения к LM Studio
по HTTP на этом ноутбуке, а не обязательное использование облака.

## Как устроено обучение

Датасет — таблица `data/dataset.csv`. Одна строка — одно письмо:
`subject` — тема, `text` — текст, `is_ai` — известная метка (0 человек, 1 ИИ).
На момент настройки в файле 2000 строк, по 1000 каждого класса. Ни в одном тексте
нет кириллицы. По исходникам человеческие примеры подготавливаются из старого
публичного корпуса SpamAssassin, а ИИ-примеры — генерацией по разнообразным запросам.
Наличие файлов само по себе не доказывает качество и достоверность меток.

`train.py` сначала удаляет нормализованные дубликаты и разделяет письма:

- `base`: учит словарную модель и средние векторы;
- `stack`: учит дерево решений на других письмах;
- `calib`: выбирает пороги;
- `test`: проверяет результат на письмах, не использованных в предыдущих шагах.

Qwen уже обучен разработчиками. Мы **не дообучаем сам Qwen**: он вычисляет векторы,
а на ваших письмах обучаются маленькие модели и пороги самого детектора.

## Какие файлы читать

| Файл | Роль |
|---|---|
| `segments.py` | Достаёт текст из `.eml`, выделяет четыре части |
| `api.py` | Запрашивает эмбеддинги и необязательные оценки LLM; кэширует ответы |
| `scoring.py` | Общие формулы оценок |
| `train.py` | Обучение, калибровка, тестовые метрики |
| `analyze.py` | Проверка нового письма обученным детектором |
| `test_my_text.py` | Ввод обычного текста для проверки |
| `server.py` | HTTP-сервис с `/analyze`, `/health` и `/docs` |
| `config.py`, `.env` | Настройки командного варианта |
| `local_qwen.py` | Отдельный запуск через локальную модель |
| `prepare_human.py` | Подготовка человеческих примеров |
| `generate_ai.py` | Генерация ИИ-примеров через настроенный разговорный API |
| `combine_dataset.py`, `check_dataset.py` | Объединение и структурная проверка данных |

## Что подготовлено для ноутбука

- Отдельное окружение Python 3.12: `.venv-local`. Скопированное `.venv` с другого
  компьютера не работает, поскольку ссылается на отсутствующий Python пользователя `kosav`.
- Модель `Qwen/Qwen3-Embedding-0.6B-GGUF`, квантование `Q8_0`, около 639 МБ.
- LM Studio предоставляет `/v1/embeddings` на `http://127.0.0.1:1234`.
- Для обращения используется постоянный идентификатор `qwen3-embedding-local`.
- Локальный запуск задаёт адрес и условный ключ `lm-studio` только своему процессу;
  исходный `.env` не изменяется. Платный ключ для этого локального сервера не нужен.
- Результаты локального обучения находятся в `model_local_qwen`, прежние — в `model`.
  Ответы эмбеддингов кэшируются в SQLite, чтобы повторно не считать одинаковый текст.
- Обнаружена RTX 4090 Laptop с 16 ГБ VRAM. Для выбранной модели этого достаточно.

## Как запускать после настройки

Открой папку проекта в Проводнике.

1. `03_LOCAL_QWEN_CHECK.bat`: запускает локальный сервер, загружает модель при
   необходимости и проверяет получение 1024 чисел.
2. `04_LOCAL_QWEN_TRAIN.bat`: обучает детектор на `data/dataset.csv` с Qwen.
   Повторяй после изменения датасета; перед каждой проверкой текста обучение не нужно.
3. `05_LOCAL_QWEN_TEXT.bat`: вставь текст, затем на новой строке напиши `END`
   и нажми Enter. Можно также перетащить UTF-8 `.txt` на этот BAT-файл.
4. `06_LOCAL_QWEN_SERVER.bat`: запускает сервис детектора на порту 8000.
   Открой `http://127.0.0.1:8000/docs`, найди `POST /analyze`, отправь `.eml`.
   Закрытие окна останавливает этот сервис. LM Studio использует отдельный порт 1234.

То же из PowerShell:

```powershell
cd C:\Users\Colorful\projects\Kirusha_AI_Email_Detector
.\.venv-local\Scripts\python.exe local_qwen.py check
.\.venv-local\Scripts\python.exe local_qwen.py train
.\.venv-local\Scripts\python.exe local_qwen.py text
.\.venv-local\Scripts\python.exe local_qwen.py text "C:\path\message.txt"
.\.venv-local\Scripts\python.exe local_qwen.py analyze "C:\path\message.eml" --json
.\.venv-local\Scripts\python.exe local_qwen.py server
```

Обычный `python analyze.py` использует старую конфигурацию `.env` и папку `model`.
Для подготовленного локального варианта используй именно `local_qwen.py` или новые BAT.
Первые два BAT проекта относятся к прежнему процессу подготовки и обучения.

## Как убедиться, что подключение реально работает

- Проверка пишет `OK: local Qwen embeddings, 1024 dimensions`.
- В `model_local_qwen/centroids.json`: `backend` равен `api`, `model` равен
  `qwen3-embedding-local`, есть непустые векторы центроидов.
- При проверке письма для поддерживаемых частей в `EMBED` стоят числа.
- `semantic_llm` пустой — это ожидаемо, разговорная модель выключена.
- Предупреждение «семантика API недоступна или не калибрована» относится к
  необязательной разговорной ветке; это не ошибка эмбеддингов.

## Ограничения, которые важно понимать команде

Векторы помогают сравнивать смысл, но сами по себе не являются надёжным признаком
ИИ-авторства. Человек и ИИ могут написать почти одинаковый текст. Высокие метрики
на одном датасете могут отражать отличия источников, тем и стиля.

Старые человеческие письма и новые генерации могут различаться эпохой, форматированием,
темами и языком. Даже честное случайное разбиение не устраняет такое смещение.
Нужен независимый тест из современных писем сопоставимых тем и источников.
Для русского языка нужны русские обучающие и тестовые примеры: многоязычный Qwen
не превращает англоязычный детектор автоматически в проверенный русскоязычный.

В данных размечено письмо целиком. Его метка переносится на все части, поэтому
выводы об отдельных частях и смешанном авторстве особенно приблизительны.
Число 0.9 в SCORE нельзя читать как «с вероятностью 90% автор — ИИ».

При замене модели эмбеддингов, квантования или обработки текста детектор следует
переобучить. Нельзя сравнивать векторы новой модели со средними векторами старой.

## Проверено при настройке 26 октября 2026

Модель скачана, загружена с GPU offload; локальный запрос вернул 1024 числа.
Детектор обучен на 2000 письмах за 57.6 секунды. Разбиение: 1340 писем для базы,
300 для дерева, 200 для калибровки, 160 для теста. Получены 7 центроидов:
по два для темы, приветствия и основного текста, один для человеческой подписи.
ИИ-подписей в выбранных базовых примерах недостаточно для второго центроида.
Оценка эмбеддингов подписи требует обоих центроидов, поэтому пока отсутствует.

Все 8 существующих тестов прошли; проверка зависимостей прошла. Дополнительно
проверены реальный локальный embedding API и обработка нового письма через
`POST /analyze` в тестовом клиенте FastAPI. Хэши исходного `.env` и пяти файлов
старой модели совпали после локального обучения.

## Перенос на компьютер коллеги

Виртуальные окружения не копируют между компьютерами. Коллеге нужны Python 3.12,
LM Studio и файлы проекта. Из папки проекта:

```powershell
py -3.12 -m venv .venv-local
.\.venv-local\Scripts\python.exe -m pip install -r requirements-local-lock.txt
lms get https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF@Q8_0 -y
.\.venv-local\Scripts\python.exe local_qwen.py train
```

Если LM Studio включает обязательную авторизацию, текущий условный ключ не подойдёт:
потребуется настроить настоящий локальный токен. Базовая настройка рассчитана на
локальный сервер без обязательной авторизации.

Источники по модели и серверу:
- https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF
- https://lmstudio.ai/docs/developer/openai-compat/embeddings
