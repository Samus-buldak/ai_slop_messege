# Как устроен новый AI Email Detector (v2)

## Главное, что изменилось

Теперь базовый детектор не нуждается в TF-IDF. Для **текста письма целиком** и отдельно для `subject`, `greeting`, `body`, `signature` берётся настоящая векторная репрезентация из установленного локально Qwen3 Embedding 0.6B (LM Studio, 1024 измерения). Длинные тексты разбиваются на перекрывающиеся фрагменты по ~3000 символов, эмбеддинги усредняются и нормируются. Это предотвращает потерю конца больших писем из-за лимита одного запроса. Ответы кэшируются по тексту/версии/модели.

По размеченным **base**-примерам создаются средние нормализованные векторы AI и HUMAN для каждой зоны, а также для письма целиком; только **base** используется для подгонки PCA-проекции полного письма на 8 компонент. Дерево получает косинусное сходство с центрами и восемь PCA-признаков настоящих Qwen-векторов — **не фиктивные hash-эмбеддинги**.

Контекстные признаки: длины письма, темы и тела, средняя длина слов, разнообразие словаря, длина предложений, вопросы, восклицания, знаки препинания, цифры, заглавные буквы, переносы строк, списки, URL, цитаты, маркеры переписки/пересылки, наличие приветствия и подписи. Дополнительно считается смысловая связность между темой и телом, приветствием и телом, телом и подписью по Qwen-векторам.

**Дерево решений действительно объединяет все эти данные как входные признаки.** Обучается на отдельной `stack`-выборке. Результат и путь дерева (`tree_decision_path`) выдаются в JSON. Итоговый скор v2 = 80% оценка дерева + 20% средняя оценка имеющихся зон; это эвристический показатель, **не откалиброванная вероятность авторства**.

## Необязательная разговорная LLM

**Qwen Embedding — не разговорная модель.** Разговорную LLM можно использовать **либо** из исходного `.env` (обычно это внешний API), **либо** как отдельную chat-модель в LM Studio. Для этого нужно обучить режим `--with-llm`. LLM получает отдельные части письма и возвращает ограниченную числом 0..1 оценку ИИ-похожести. На этих оценках и остальных признаках обучается **отдельное дерево `with_llm`**. Всегда создаётся независимое дерево `no_llm`, чтобы при отключении/ошибке LLM переключиться на верно обученную модель, а не заполнять её пропущенные признаки нулями.

**По умолчанию локальный запуск (`03`–`08`) не использует старую LLM из `.env`**: все его запросы идут на `http://127.0.0.1:1234/v1`. Включение `--llm-from-env` — отдельное явное согласие направлять части писем во внешний API из `.env`, оставляя эмбеддинги Qwen локальными. Обычные `train.py` / `analyze.py` вне `local_qwen.py` по-прежнему могут использовать исходный `.env` целиком.

## Как запускать (Windows)

Используй папку со своей рабочей `.venv-local`, LM Studio и оригинальным `.env`; **не удаляй их**. Распакуй патч поверх папки проекта или скопируй файлы обновлённой версии с заменой.

```powershell
# Находясь в корне проекта
.\.venv-local\Scripts\python.exe local_qwen.py check
.\.venv-local\Scripts\python.exe local_qwen.py train
.\.venv-local\Scripts\python.exe local_qwen.py text
.\.venv-local\Scripts\python.exe local_qwen.py analyze "letter.eml" --json
.\.venv-local\Scripts\python.exe local_qwen.py server
```

Или нажимай `03`, `04`, `05`, `06` BAT-файлы. Само обучение проводится **один раз на датасете** и повторяется после изменения данных/модели. Для каждого нового текста переобучение не требуется.

**Подключить ТВОЮ chat-LLM из `.env` к локальному Qwen (гибрид):**

Убедись, что исходный `.env` сохранён и содержит `API_KEY`, `API_URL`, `MODEL` от работающей разговорной LLM. Не переименовывай их и не вставляй токены в BAT. Эмбеддинги всегда остаются на `127.0.0.1:1234`, а непустые фрагменты писем (до 1200 символов каждый) отправляются модели из `.env` по `/chat/completions`. **Это не полностью локальный режим, он может расходовать лимиты API и передавать содержимое писем стороннему провайдеру.**

Запускай **09_QWEN_ENV_LLM_TRAIN.bat** один раз для обучения, затем **10_QWEN_ENV_LLM_TEXT.bat** для проверки текста или **11_QWEN_ENV_LLM_SERVER.bat** для своего API.

Эквивалентные команды:

```powershell
.\.venv-local\Scripts\python.exe local_qwen.py train --llm-from-env --with-llm
.\.venv-local\Scripts\python.exe local_qwen.py text --llm-from-env
.\.venv-local\Scripts\python.exe local_qwen.py analyze --llm-from-env "letter.eml" --json
.\.venv-local\Scripts\python.exe local_qwen.py server --llm-from-env
```

На обучении будут созданы `no_llm` и `with_llm` деревья. При обычном запуске `05_LOCAL_QWEN_TEXT.bat` LLM-ветка не включится, но `no_llm` дерево продолжит работать. Если провайдер не отвечает или хотя бы одна непустая зона не получила оценку, автоматически используется `no_llm`. Чтобы изменить конфигурацию/модель LLM и сохранить корректность `with_llm`, переобучи детектор. Модель по умолчанию не обучается заново при каждом письме.

**Альтернатива: полностью локальная chat-LLM в LM Studio:**

1. В LM Studio оставь загруженной модель `qwen3-embedding-local` и загрузи ещё chat Qwen. Убедись, что она доступна по `/v1/chat/completions` и узнай её ID.
2. Запусти `07_LOCAL_QWEN_TRAIN_WITH_LLM.bat`, укажи ID. Или:

```powershell
.\.venv-local\Scripts\python.exe local_qwen.py train --llm-model "ТОЧНЫЙ_ID_CHAT_МОДЕЛИ" --with-llm
.\.venv-local\Scripts\python.exe local_qwen.py text --llm-model "ТОЧНЫЙ_ID_CHAT_МОДЕЛИ"
```

При проверке/серверном запуске используй **тот же ID**, иначе детектор честно перейдёт на `no_llm`. При желании задай `LOCAL_LLM_MODEL` в терминале для этой сессии (PowerShell `$env:LOCAL_LLM_MODEL="..."`). Для сервера:

```powershell
.\.venv-local\Scripts\python.exe local_qwen.py server --llm-model "ТОЧНЫЙ_ID_CHAT_МОДЕЛИ"
```

**Включить TF-IDF для сравнения** (по умолчанию выключен):

```powershell
.\.venv-local\Scripts\python.exe local_qwen.py train --use-tfidf
```

Есть отдельный `08_LOCAL_QWEN_TRAIN_WITH_TFIDF.bat`. Он **переобучит** новую v2 модель в той же папке и перезапишет результаты; если хочешь честно сравнить две версии, сначала сохрани копию `model_hybrid_qwen/`.

Обучить TF-IDF-режим без Qwen, если локальный сервер недоступен (только отладка):

```powershell
$env:DETECTOR_MODEL_DIR="model_offline_test"
python train.py --offline --use-tfidf
```

## Файлы и модель

| Файл | Что делает |
|---|---|
| `segments.py` | MIME/HTML → текст и 4 зоны; исключает HTML blockquote, цитируемые ответы и пересылки |
| `embedding_pipeline.py` | перекрывающиеся фрагменты длинных писем, нормировка, PCA Qwen |
| `context_features.py` | 21 контекстный признак |
| `signals_v2.py` | один и тот же порядок признаков при обучении и анализе |
| `api.py` | Раздельные OpenAI-compatible запросы локальных Qwen эмбеддингов и опциональной chat LLM из `.env`; JSON-валидация и SQLite-кэш |
| `scoring.py` | скоринг зон и фиксированная схема признаков v2 |
| `train.py` | `base` → `stack` → `calib` → `test`; 1 или 2 дерева |
| `analyze.py` | проверка нового письма, сегменты, контекст, путь дерева, предупреждения |
| `local_qwen.py` | локальные Qwen-эмбеддинги и явный выбор chat-провайдера (`--llm-from-env` либо `--llm-model`) |
| `server.py` | `POST /analyze`, `GET /health`; API-документация `/docs` |

Новые веса/пороги/отчёт: `model_hybrid_qwen/tree.pkl`, `centroids.json`, `thresholds.json`, `test_metrics.json`. Файл `tfidf.pkl` присутствует ради совместимости, но если TF-IDF выключен, он содержит только `None` (без словаря и без обученного TF-IDF классификатора).

**Важно**: нельзя считать старую `model_local_qwen` новой v2. После распаковки **запусти обучение заново** в `model_hybrid_qwen`. Архив не содержит ни новых обученных весов дерева, ни локально скачанной модели Qwen. Оригинальные артефакты v1 для совместимости остаются на месте.

## Ограничения

- Детектирование ИИ-авторства ненадёжно по коротким фрагментам, шаблонной переписке и текстам после правок; вывод не является доказательством.
- В предоставленных исходных данных человеческие письма и ИИ-примеры разных источников и периодов; сильные метрики на старом/синтетическом датасете могут отражать источник, а не авторство. Для русских писем нужны русские размеченные примеры.
- В датасете задана **метка письма**, а не каждой его части. Зональные оценки лишь приблизительные; смешанное авторство плохо валидировано.
- Уровень `AI`, `HUMAN`, `UNCERTAIN` строится по порогам отдельной калибровочной выборки. При недоступности Qwen реальная локальная модель v2 не заменяет векторы хэшами и возвращает `UNCERTAIN`.
- В гибридном режиме при тренировке и анализе непустые зоны отправляются внешнему chat API, могут взиматься платежи и применяться правила хранения данных провайдера. По умолчанию внешний API НЕ вызывается при локальном запуске.
- Для LLM нет гарантии корректности ответа: JSON и диапазон проверяются, ошибки не кладутся в кэш. Содержимое писем передаётся модели как недоверенные данные, но полной защиты от prompt injection нет.
- Если поменял Qwen, версию, ID, сегментацию, обучай **все артефакты v2 заново**.
- `pickle` требует доверенного происхождения файлов; не загружай веса моделей от неизвестных людей.
