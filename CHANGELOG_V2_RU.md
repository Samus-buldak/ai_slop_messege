# Отчёт о внесённых изменениях — Kirusha AI Email Detector v2

## Исходное состояние

В архиве была v1: TF-IDF/логистическая регрессия + по четыре зональных Qwen cosine score + одно дерево решений из 10 признаков. LLM-оценки не участвовали в обучении дерева, а только корректировали итог. Локальная модель Qwen3 Embedding была подключена через LM Studio, её работа на исходном ПК отдельно здесь не перепроверялась.

## Сделано

1. В `train.py` TF-IDF отключён по умолчанию; включается `--use-tfidf` для сравнительного эксперимента. Реально обучаются одно или два дерева. Для LLM создаётся независимое `with_llm` дерево; `no_llm` не использует LLM-признаки.
2. `embedding_pipeline.py`: настоящие эмбеддинги Qwen для всех частей + всего письма; перекрывающиеся куски длинного текста; нормированное усреднение; обученная **только на base** 8-компонентная PCA-проекция Qwen-векторов. Нет поддельных hash-векторов.
3. `context_features.py`: 21 интерпретируемый стилевой/контекстный признак, вычисляемый локально.
4. `signals_v2.py`: единый конвейер формирования признаков для train/test/inference; добавлены сходства Qwen с AI/HUMAN-центрами и смысловая согласованность частей письма.
5. `scoring.py`: фиксированная схема признаков v2, отдельные оценки `no_llm`/`with_llm`; итог: дерево 80%, зоны 20%. Скоры не считаются достоверными вероятностями.
6. `segments.py`: улучшена MIME/HTML-обработка; удаление цитируемых HTML-блоков, ответных цепочек, пересланных фрагментов, типичных email-подписей и футеров.
7. `analyze.py`: добавлены вывод контекстных/Qwen-признаков, путь решений дерева, выбор правильной версии дерева и режим `UNCERTAIN` при недоступности Qwen; поддерживается чтение старых v1-артефактов.
8. `local_qwen.py`: отдельная новая папка `model_hybrid_qwen`, локальный HTTP без облака, работа при уже поднятом LM Studio, возможность указать `--llm-model`.
9. Новые `07_LOCAL_QWEN_TRAIN_WITH_LLM.bat`, `08_LOCAL_QWEN_TRAIN_WITH_TFIDF.bat`, README и автоматические тесты.

## Проверено в этой среде

- `python -m pytest -q`: **15 тестов прошли** (8 старых + 7 новых); 4 предупреждения касаются версий sklearn в старых v1 pickle, не падений.
- Режим `python train.py --offline --use-tfidf --csv data/demo_synthetic.csv`: прошёл весь цикл base/stack/calib/test, записал артефакты v2; `python analyze.py sample.eml --json` вернул полный отчёт, включая путь дерева.
- Проведена интеграционная проверка с **тестовым HTTP-сервером, имитирующим LM Studio**: обучение v2 без TF-IDF с `--with-llm`, сохранение двух деревьев, 1024-мерные тестовые векторы, анализ нового письма в режимах `with_llm` и `no_llm`, 8 PCA-признаков и JSON-вывод — прошли. **Имитация не является проверкой реальной модели Qwen.**
- Локальные эмбеддинги и разговорная LLM настоящего ПК не доступны для проверки в этом окружении. Нельзя честно объявить, что GPU, LM Studio, chat-модель и полное **Qwen-only** обучение уже проверены на пользовательской машине. После распаковки проверь через `03` → `04` → `05`; chat-режим — через `07`.
- Результат на синтетическом демо-CSV **не является доказательством точности** на реальных email; число метрик не переносится автоматически на другие источники.

## Безопасная установка

Копируй новый код из патча поверх **существующей папки** проекта. Не удаляй `.env`, `.venv-local`, собственные исходные датасеты, LM Studio и прежние обученные модели. В выдаваемом архиве нет `.env`, приватных токенов, `venv`, старых больших SQLite-кэшей или самой модели Qwen.

Данные `data/dataset.csv` включены **только в полном архиве**. Для простого обновления кода предпочтителен патч.

## Дополнение v2.1 — гибрид `.env` + локальный Qwen

- Исправлен пробел v2: в локальном запуске LLM из существующего `.env` раньше **не** использовалась. Теперь для этого есть явный `--llm-from-env`.
- `config.py` и `api.py` поддерживают отдельные `SEMANTIC_API_URL`, `SEMANTIC_API_KEY`, `SEMANTIC_MODEL` для chat-LLM, сохраняя локальные `API_URL`, `API_KEY`, `EMBED_MODEL` для Qwen embeddings.
- `local_qwen.py` извлекает из исходного `.env` только `API_URL`, `API_KEY`, `MODEL` **до** локальной подмены и не печатает секреты. Обычный режим без флага полностью локален.
- `train.py` сохраняет URL/ID chat-модели в `thresholds.json` (без секретного токена); `analyze.py` выбирает `with_llm` только при совпадении модели и URL, иначе использует `no_llm`.
- Новые Windows BAT: `09_QWEN_ENV_LLM_TRAIN.bat`, `10_QWEN_ENV_LLM_TEXT.bat`, `11_QWEN_ENV_LLM_SERVER.bat`.
- Добавлены три теста гибридного режима, в том числе проверка раздельных адресов и токенов. `pytest -q`: **18 passed** (4 предупреждения sklearn из-за старых pickle).
- **Не проверено**: реальный внешний API пользователя и реальный LM Studio; только изолированные HTTP-моки. Пересылаемые фрагменты писем могут содержать чувствительные данные, учти политику внешнего API.
